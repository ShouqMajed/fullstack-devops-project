# Full Stack DevOps Project

A complete DevOps implementation for building, testing, containerizing, deploying, and monitoring a full-stack web application using modern CI/CD practices.

The application consists of an **Angular frontend**, **Spring Boot backend**, and **MySQL database**, deployed on a Kubernetes cluster hosted on AWS.

---

## 🚀 Project Overview

This project demonstrates an end-to-end DevOps workflow for a full-stack application.

The main goal was to automate the software delivery lifecycle from source code management to production deployment using:

**GitHub → Jenkins → SonarQube → Nexus → Docker → Ansible → Kubernetes → Grafana**

The CI/CD pipeline automatically builds and tests the application, analyzes code quality, stores build artifacts, creates Docker images, pushes them to Docker Hub, and deploys the application to Kubernetes.

## ☁️ Infrastructure

The project infrastructure was deployed on **AWS EC2** using four virtual machines with separate responsibilities:

| Server            | Responsibility                                                              |
| ----------------- | --------------------------------------------------------------------------- |
| Jenkins Server    | Runs the CI/CD pipeline, builds/tests the application, and triggers Ansible |
| Docker Server     | Builds Docker images and pushes them to Docker Hub                          |
| Kubernetes Master | Manages the Kubernetes cluster and deployment manifests                     |
| Kubernetes Worker | Runs the frontend, backend, and MySQL application workloads                 |

The Kubernetes cluster was configured using **kubeadm**.

---

## 🔄 CI/CD Pipeline

The Jenkins pipeline automates the complete application delivery workflow:

1. Checkout source code from GitHub
2. Build the Spring Boot backend
3. Run backend tests
4. Install and build the Angular frontend
5. Run frontend tests
6. Perform SonarQube code analysis
7. Validate the SonarQube Quality Gate
8. Upload backend and frontend artifacts to Nexus
9. Trigger Ansible to build Docker images
10. Push Docker images to Docker Hub
11. Deploy the application to Kubernetes using Ansible
12. Send email notifications for pipeline results

---

## 🔍 Code Quality — SonarQube

SonarQube is integrated into the CI pipeline to perform:

* Static code analysis
* Bug detection
* Code smell detection
* Security vulnerability analysis
* Quality Gate validation

The pipeline waits for the **Quality Gate** result before continuing to the next stages.

---

## 📦 Artifact Management — Nexus

Nexus Repository is used to store versioned build artifacts generated by Jenkins.

Artifacts include:

* Backend `.jar` package
* Frontend `.tgz` package

Artifact versions are associated with the Jenkins build number.

## 🐳 Docker Containerization

Separate Docker images are created for the frontend and backend.

### Backend

The backend Dockerfile:

* Builds the Spring Boot application using Maven
* Generates the packaged JAR
* Runs the application using Java Runtime

### Frontend

The frontend Dockerfile:

* Builds the Angular application using Node.js
* Generates production static files
* Serves the application using Nginx

### Docker Images

```text
shouqmajed/app-backend
shouqmajed/app-frontend
```

Docker image creation and publishing are automated through **Ansible**.

---

## ☸️ Kubernetes Deployment

The application is deployed inside the dedicated Kubernetes namespace:

```text
fullstack-app
```

The Kubernetes environment contains:

* Angular frontend
* Spring Boot backend
* MySQL database
* Services
* Persistent storage
* Ingress

### MySQL

Persistent storage is configured using:

* PersistentVolume (PV)
* PersistentVolumeClaim (PVC)

This ensures that database data persists independently of the MySQL pod lifecycle.

---

## 🌐 Ingress Routing

Kubernetes Ingress exposes the application and routes incoming requests.

```text
/           → Frontend
/customers  → Backend
```

This allows the Angular frontend to communicate with the Spring Boot API through the Kubernetes environment.

---

## ⚙️ Deployment Automation with Ansible

Ansible is used in two major parts of the deployment process.

### Docker Automation

Ansible:

* Builds frontend and backend Docker images
* Tags the images
* Pushes them to Docker Hub

### Kubernetes Automation

Ansible automatically applies the Kubernetes configuration files and deploys the complete application environment.

This provides consistent and repeatable deployments.
